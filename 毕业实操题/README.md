## 三、项目任务书

### 项目 01 · 命令行学生成绩系统

**背景**：班主任需要一个不依赖 Excel 的小工具，用命令行管理班级成绩。

**功能需求**

| 命令 | 说明 | 示例 |
|------|------|------|
| `add <姓名> <分数> [-s 科目]` | 添加一条成绩，分数 0~100 | `app.py add 小明 92` |
| `list [--sort score\|name]` | 列出全部，默认按分数降序 | `app.py list --sort name` |
| `search <关键字>` | 姓名模糊查询 | `app.py search 小` |
| `rank [-n 3]` | 前 N 名 | `app.py rank -n 3` |
| `stats` | 人数、平均分、最高/最低、及格率 | `app.py stats` |
| `export <out.csv>` | 导出 CSV（utf-8-sig） | `app.py export out.csv` |

**技术要求**

- 数据模型用 `@dataclass`，存储用 JSON（`students.json`）
- 分数非法（越界/非数字）→ 友好报错，退出码 2
- 同名 + 同科目视为重复，提示后拒绝
- 读写文件用 `with` + `encoding="utf-8"`；JSON 损坏时给提示而不是崩溃
- 测试用 `tmp_path`/`TemporaryDirectory`，不要污染真实数据

**验收清单**

- [ ] 6 个命令全部可用，`--help` 完整
- [ ] 连续 add 3 条后退出再启动，数据仍在
- [ ] 输入 `abc`、`-5`、`101` 均被拦截且有中文提示
- [ ] `export` 出的 CSV 用 Excel 打开不乱码
- [ ] ≥6 个测试全绿，含 1 个“JSON 文件损坏”用例

**加分项**：支持 `add-many` 从 CSV 批量导入；支持按科目分组统计。

### 项目 02 · 并发日志分析器

**背景**：线上有 5 个日志文件，需要统计错误分布、慢接口，并对比串行/并行耗时。

**功能需求**

1. `make_logs.py`：生成 5 个样例日志文件（每份 5000 行），行格式：
   `2026-11-12 10:23:01 [ERROR] GET /api/pay 失败 1500ms`
2. `analyze.py <日志目录>`：
   - 流式逐行读取（生成器），不得一次性读入内存
   - 正则解析出时间、级别、方法、路径、耗时
   - 输出：各级别条数、各接口平均耗时 Top5、WARNING/ERROR 且 ≥500ms 的慢请求清单
3. 并发：用 `ThreadPoolExecutor` 同时分析多个文件，`--workers` 可配
4. 报告：写 `report.json` + `report.md`（含串行 vs 并行耗时对比）
5. 剖析：用 `cProfile` 找一次热点，在 README 里说明优化前后差异

**技术要求**

- 正则必须使用**命名分组**（`(?P<level>...)`）
- 统计用 `Counter` / `defaultdict`
- 坏行（无法解析）跳过并计数，不中断
- 汇总结果时注意线程安全（在主线程汇总）

**验收清单**

- [ ] 5 个文件分析结果与“单文件逐个跑”一致
- [ ] 日志 10 万行时内存占用平稳（生成器生效）
- [ ] 坏行计数准确，程序不崩
- [ ] `report.md` 含耗时对比表
- [ ] ≥5 个测试：解析函数、坏行、慢请求筛选、统计正确性

**加分项**：按分钟聚合错误数，连续 2 分钟 ≥3 次 ERROR 输出“疑似故障”告警。

### 项目 03 · SQLite 任务管理器

**背景**：一个支持优先级和截止日期的个人任务管理 CLI，数据落 SQLite。

**表结构（必须）**

```sql
CREATE TABLE tasks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    priority INTEGER CHECK (priority BETWEEN 1 AND 5),
    due_date TEXT,              -- YYYY-MM-DD
    status TEXT DEFAULT 'todo', -- todo / done
    created_at TEXT NOT NULL
);
```

**功能需求**

| 命令 | 说明 |
|------|------|
| `add <标题> [-p 1-5] [-d 2026-12-31]` | 新建任务 |
| `list [--status todo\|done\|all] [--overdue]` | 列表，默认未完成，按优先级+截止日排序 |
| `done <id>` | 标记完成（不存在的 id 报错） |
| `delete <id>` | 删除，需二次确认（`--yes` 跳过） |
| `search <关键字>` | 标题模糊查询（参数化 LIKE） |
| `import <csv>` | 批量导入：**事务**，任何一行非法则整体回滚 |
| `export <json>` | 导出全部任务 |

**技术要求**

- 全部查询**参数化**，禁止字符串拼接 SQL
- `import` 用事务 + 逐行校验；错误行号写进错误信息
- 建索引：`status + due_date` 联合索引；建视图 `v_overdue`（未完成且已过期）
- 连接管理用 `contextmanager`，退出自动 commit/rollback/close
- 测试用 `:memory:`；≥6 个用例（含事务回滚、重复 done）

**验收清单**

- [ ] 7 个命令全部可用
- [ ] `import` 含一条坏数据时，数据库条数保持不变（回滚生效）
- [ ] `EXPLAIN QUERY PLAN` 显示列表查询走了索引
- [ ] SQL 注入字符串（`' OR '1'='1`）无法绕过 search
- [ ] 测试全绿，测试之间互不影响

**加分项**：`list` 支持分页（`--page/--size`）；`stats` 输出各状态数量与逾期数。

### 项目 04 · 电商数据报表流水线

**背景**：运营每周要一份“订单分析包”，包含清洗报告、Excel 多表、图表、Word 摘要。

**流程（必须分步实现，每步可单独调用）**

1. `generate`：生成 5000 行模拟订单 CSV，**故意包含脏数据**：缺失金额、重复订单号、负金额、非法日期
2. `clean`：清洗并输出清洗报告（每类脏数据各多少条、怎么处理）
3. `analyze`：按品类×城市透视 GMV；按月/周趋势；客单价分箱；Top10 用户
4. `chart`：生成 3 张图（趋势折线、品类柱状、金额分布直方图），保存 PNG
5. `report`：导出 `report.xlsx`（≥4 个 sheet）+ `report.docx`（标题、摘要、Top3 表格）

**技术要求**

- 清洗规则要**写进代码注释**并输出统计，不许静默丢弃
- 透视用 `pivot_table`；分箱用 `pd.cut`；时间用 `resample`
- 图表必须处理中文与负号；用 Agg 后端保存
- Word 表格样式 `Table Grid`；Excel 设置列宽与表头样式
- CLI：`python app.py all --month 2026-11`

**验收清单**

- [ ] 脏数据 4 类全部被识别并记录
- [ ] Excel 打开后 4 个 sheet 内容正确、无乱码
- [ ] 3 张 PNG 清晰、中文正常
- [ ] Word 含摘要段落 + 排名表格
- [ ] ≥5 个测试：清洗规则、透视结果、分箱边界

**加分项**：给趋势图加 7 日移动平均与峰值标注；支持 `--dry-run` 只打印计划不落盘。

### 项目 05 · 异步并发采集器

**背景**：需要并发“采集” 50 个 URL 的内容，要求限流、重试、断点续跑。

**功能需求**

1. `fetch(url)`：用 `asyncio.sleep` 模拟网络（随机 0.05~0.8s），20% 概率失败
2. 调度：`N` 个 worker 从 `asyncio.Queue` 取任务；全局并发上限 `--limit 5`
3. 重试：单 URL 最多 3 次，退避间隔 0.2s / 0.4s / 0.8s；全部失败记入 `failed.json`
4. 断点续跑：成功的 URL 写入 `done.json`；再次运行自动跳过
5. 输出 `results.json`（url、大小、耗时、尝试次数）与终端进度（完成数/总数）
6. 取消：捕获 `KeyboardInterrupt`，优雅退出并保存已完成部分

**技术要求**

- 必须用：`asyncio.Queue` + `Semaphore` + `wait_for` + `gather`
- worker 数量与并发上限分离（worker 多不代表并发高）
- 所有落盘操作在主协程完成（避免并发写文件）
- 测试：用 `unittest.IsolatedAsyncioTestCase` + `AsyncMock` 模拟 fetch

**验收清单**

- [ ] 50 个 URL 全部有终态（成功/失败），无遗漏
- [ ] 并发上限生效（日志中同时运行数 ≤ limit）
- [ ] 第二次运行跳过已成功 URL
- [ ] 失败 URL 有 3 次尝试记录
- [ ] 测试全绿（≥4 个异步用例）

**加分项**：给每个 URL 设置独立超时；输出“平均耗时/成功率”小报告（Markdown）。

### 项目 06 · 综合自动化运维脚本

**背景**：给一台无人值守的 Windows 机器做“每日自动备份”，要能交给任务计划程序。

**功能需求**

```bash
python backup.py backup  --src D:\data --out D:\backups --keep 5
python backup.py verify  --src D:\data --archive D:\backups\20261112.zip
python backup.py prune   --out D:\backups --keep 5
python backup.py report  --out D:\backups --to ops@example.com
```

1. `backup`：打包 zip（跳过 `__pycache__/.git/临时文件`）+ 生成 sha256 清单 + 校验
2. `verify`：对比源目录与清单，报告新增/修改/缺失
3. `prune`：只保留最近 N 份，其余删除（先 dry-run 打印再删）
4. `report`：生成 Markdown 摘要 + `alert.eml`（邮件草稿，不真发）
5. `--dry-run`：所有命令支持，只打印将发生的操作
6. 全程 logging 到文件；退出码：0 成功 / 1 校验失败 / 2 参数或环境错误

**技术要求**

- 目录遍历用 `pathlib`；哈希分块读取
- 文件名带日期；同名冲突自动加序号
- 敏感信息（收件人、SMTP）从环境变量读，缺失时降级为“只生成本地报告”
- 测试：临时目录里跑全流程，≥5 个用例（备份内容、校验失败、prune 保留数、dry-run 不落盘）

**验收清单**

- [ ] 连续跑 3 次生成 3 个归档，内容可解压
- [ ] 篡改源文件后 `verify` 返回 1 且指出具体文件
- [ ] `prune --keep 2` 后只剩最新 2 个
- [ ] `--dry-run` 前后目录完全无变化
- [ ] 日志文件包含时间戳与级别；`report.md` 可读
- [ ] 测试全绿

**加分项**：支持增量备份（哈希未变则跳过）；生成“恢复指引”段落。
